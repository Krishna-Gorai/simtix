# SIMTiX throughput at 4, 8 and 16 lanes, every benchmark (2026-11-19)

Generated by `python docs/plot_lanes_throughput.py`; data in docs/lanes_throughput.csv.

- docs/figs/lanes_throughput.pdf: PULP style (Ara TVLSI Figs. 5-6): log2 axis, a peak line per
  lane count with the region under it shaded, square/triangle/circle = 4/8/16 lanes per benchmark.
- docs/figs/lanes_throughput_heatmap.pdf (green, the default; variants _green, _viridis, _warm, _blue): Ara2 style: cell = lane operations per cycle, colour =
  fraction of the peak.

Throughput = lane operations per cycle = sum over a case's launches of the active lanes of the
issued warp instructions, divided by the sum of the cycles (thread instructions executed per
cycle); peak = L. It counts every executed thread instruction (address arithmetic and loop
control included), so it measures how busy the lanes are, not useful FLOPs (the supplement's
throughput table gives FLOP/MAC per cycle for 15 kernels). The instruction count is the same at
every lane count except reduce_shfl, scan and seg. scan, which add a shuffle step per doubling.
Same board-size simulations as docs/lanes_scaling.md (54 cases, all outputs checked).
